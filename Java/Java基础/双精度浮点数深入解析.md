# 指数位为什么是 11 位，尾数为什么52 位？

为什么不多给一位或者少给一位？这是权衡的结果：

- **如果指数位更多**：比如 15 位。那么 `double` 能表示的范围会巨大（比如可以存下宇宙中原子的总数），但代价是**精度变差**。因为 64 位总数不变，指数位占多了，尾数位就少了，小数点后的位数就短了。
    
- **如果指数位更少**：比如 8 位（像 `float`）。那么精度虽然高，但稍微大一点的数字（如超过 $10^{38}$）就会“溢出”变成无穷大。
    

**11 位指数 + 52 位尾数** 是经过数学家和工程师精确计算后的“黄金比例”，它既能保证我们处理日常天文数字（最大 $1.8 \times 10^{308}$）不会溢出，又能保证小数点后有 15-17 位的精确度。


# 为什么指数位的数值相对与真实数值要偏移1023

### 1. 为了让比较变得“无脑”快

计算机经常需要比较两个浮点数的大小。

- **如果不偏移（使用补码或符号位）**：
    
    指数既有正数（如 $2^5$）又有负数（如 $2^{-5}$）。在二进制补码中，负数通常以 `1` 开头。如果直接比较，计算机会认为负数指数比正数指数大（因为首位是 1），这需要额外的逻辑去判断符号。
    
- **使用偏移（Bias）后**：
    
    我们将所有的指数都加上 $1023$。
    
    - 实际指数 $-1022$ 变成：$-1022 + 1023 = 1$（二进制：`00000000001`）
        
    - 实际指数 $0$ 变成：$0 + 1023 = 1023$（二进制：`01111111111`）
        
    - 实际指数 $1023$ 变成：$1023 + 1023 = 2046$（二进制：`11111111110`）
        

**结果**：所有的指数都变成了**非负数**。计算机在比较两个浮点数时，可以直接从左往右按位比较二进制。谁的“指数位”二进制数值大，谁的绝对值就大。这种方法让 CPU 的比较电路设计得极其简单且高效。

---

### 2. 预留特殊值

指数位全 `0` 和全 `1` 是被特殊对待的：

- **全 `0` (`000...0`)**：用于表示 **0** 或极小的“非规格化数”。
    
- **全 `1` (`111...1`)**：用于表示 **无穷大 (Infinity)** 或 **非数字 (NaN)**。
    

因为偏移量是 $1023$，我们可以表示的有效指数范围是 $1$ 到 $2046$。减去偏移量后，对应实际的物理指数范围就是 $-1022$ 到 $+1023$。

---

### 3. 为什么是 1023 而不是 1024？

`double` 的指数位有 11 位，能表示的数字范围是 $0 \sim 2^{11}-1$（即 $0 \sim 2047$）。

公式是：$Bias = 2^{k-1} - 1$（$k$ 是位数）。

- 对于 11 位的 `double`：$2^{11-1} - 1 = 1024 - 1 = 1023$。
    
- 如果偏移量是 1024，正负区间就不平衡了。使用 1023 可以让正指数和负指数的分布几乎完全对称，非常完美地利用了存储空间
