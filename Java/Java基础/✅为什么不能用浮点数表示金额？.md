# 📖 Java 双精度浮点数 (IEEE 754) 核心笔记

## 1. 为什么浮点数不能用于高精度计算？

在 Java 中，`double` 和 `float` 并不是为了“精确”而设计的，而是为了“快速”和“大范围”设计的。

- **二进制局限性**：十进制中的 $0.1$、$0.2$ 等在二进制中是**无限循环小数**（就像 $1/3$ 在十进制中是 $0.333...$ 一样）。
    
- **精度截断**：由于 `double` 只有 52 位尾数空间，必须对无限循环的二进制进行“舍入/截断”。
    
- **误差累积**：单次计算的微小误差在多次运算（如金融加总）后会迅速放大，导致 `1.1 + 0.1 = 1.2000000000000002` 这样的结果。
    
- **解决方案**：在涉及货币等精确场景，必须使用 `java.math.BigDecimal`。

## 2. 十进制小数转双精度浮点数过程

计算机存储 `double` 时遵循 **IEEE 754 标准**，将其分为三部分：

1. **符号位 (Sign)**: 1位 (0为正，1为负)
    
2. **指数位 (Exponent)**: 11位 (偏移量 Bias = 1023)
    
3. **尾数位 (Fraction)**: 52位 (隐藏首位1)

            long bits = Double.doubleToRawLongBits(n);

        }
    }

## 3. 两个双精度浮点数的计算过程

当计算机执行 `double a + double b` 时，底层遵循以下逻辑：

1. **对阶 (Alignment)**：
    
    - 比较两个数的指数位。
        
    - 将指数较小的数的小数点向左移动，使其指数与较大的数一致。
        
    - _注意：移动过程中，较小数的末尾位可能会丢失（精度损失）。_
        
2. **尾数求和**：
    
    - 将两个对齐后的尾数进行二进制加法。
        
3. **规格化 (Normalization)**：
    
    - 如果结果不是 $1.xxxx$ 的形式（比如产生了进位），则重新移动小数点并调整指数。
        
4. **舍入 (Rounding)**：
    
    - 根据 52 位的限制进行最后的舍入。

## 4. 十六进制相关知识点

在调试浮点数时，Java 提供的 `0x...p...` 格式是最高效的观察方式。

### 核心语法解读

> 示例：`0x1.b8b4395810625p1`

- **`0x`**：表示这是十六进制。
    
- **`1.`**：固定的前缀，代表二进制科学计数法中隐藏的那个 `1`。
    
- **`b8b4...`**：尾数部分的十六进制表示。1位十六进制 = 4位二进制（例如 `b` = `1011`）。
    
- **`p`**：代表 **Power**，即指数开始。
    
- **`1`**：代表 **2 的几次幂**（这里是 $2^1$）。
    

### 为什么用十六进制？

- **无损转换**：十六进制和二进制之间可以完美互转，不会像十进制转二进制那样产生新的误差。
    
- **易于阅读**：64 位二进制太长，十六进制只需要 13 位左右就能完整表达。
